# Работа с Codex

## Начать задачу

Из корня проекта запустите `codex`. Для существенной задачи: `/plan` и описание
желаемого результата, ограничений, сохраняемого поведения; приложите макет или
пример ошибки. Агент читает проектный контекст и engineering-workflow, затем
подходящие навыки Superpowers. Сам `/plan` плагины не включает.
После обсуждения утвердите план, выйдите из Plan Mode через Shift+Tab и напишите
«Реализуй согласованный план». План сохраняется до реализации и делегирования;
далее исполнение и исправления проходят без постоянных подтверждений.
Маленькие очевидные исправления можно задавать в обычном режиме.

Явный запуск: `$engineering-workflow` с описанием задачи или выбор через `/skills`.
Для ревью: «Проверь результат по утверждённым требованиям и правилам проекта».
Автоматический выбор навыка зависит от его описания и инструкций; при подозрении
проверьте `/skills` и сообщение агента о действительно прочитанных навыках.
Новая установка проверяется в новой сессии, старый контекст не обновляется задним числом.

## Установка на другой машине

`./bin/dotfiles install --package codex --dry-run` показывает конфликты.
Существующий ~/.codex/AGENTS.md сохраняйте через явный `--backup-conflicts`,
затем выполните install. Не стовьте целиком ~/.codex: авторизация, config.toml,
история, plugin cache и доверенные пути остаются локальными.
Роли лежат в ~/.codex/agents; основной модели нет жёсткой привязки.
Простой исполнитель использует gpt-6-luna, интегратор и ревьюер наследуют основную.
Недоступность роли/модели агент сообщает и использует основную модель честно.
В локальном config.toml задайте поддерживаемую основной моделью максимальную
plan_mode_reasoning_effort; на проверенной gpt-6.1-sol это ultra.
Не переносите это значение вслепую на модели с другим набором уровней.

Superpowers устанавливается отдельно через `/plugins` из официального каталога.
Убедитесь, что навыки видны через `/skills` и в `codex debug prompt-input`.
Если plugin установлен, но навыки не загружаются, используйте native fallback:
`codex-superpowers-link /absolute/path/to/installed/superpowers`.
Источник должен быть стабильным проверенным checkout/cache конкретной версии;
путь не содержит секретов, но машинный путь в dotfiles не записывается.
Отключите plugin в локальном config.toml, чтобы не было двух источников навыков.
Helper предварительно проверяет конфликты и никогда не заменяет чужие файлы.
Для обновления сначала отключите старый источник, сохраните/снимите только его
управляемые ссылки, затем подключите проверенную новую версию. Не меняйте cache
плагина вручную. При исправлении native plugin discovery уберите fallback-ссылки
и включите plugin; не держите оба способа активными.

## Новый проект

Создайте корневой AGENTS.md с указателем на источник архитектуры и требований,
командами проверок, границами полномочий и местом сохранения планов. Не копируйте
в него личные модели и общий процесс. Укажите, что ai-context описывает намерения,
а код/контракты/проверки — реализованное и подтверждённое поведение.
Начальный план содержит Goal, Context, Scope, Interfaces, Steps и Acceptance;
статус и доказательства ведутся внутри dossier. Используйте имеющийся формат
проекта; новые номера проверяйте на уникальность. Не создавайте очередь ради
очереди. Подключение проекта не требует установки нового приложения.

## Figma: необязательный локальный пилот

Кандидат: https://github.com/grab/cursor-talk-to-figma-mcp
Схема: Community plugin → локальный WebSocket relay → stdio MCP → Codex.
Bun нужен локально. Не запускайте upstream `setup`: он настраивает Cursor.
Используйте фиксированный проверенный commit, установите его lockfile-зависимости
в отдельный каталог вне dotfiles, запустите relay вручную, ограничив loopback.
MCP запускает `bun /absolute/path/to/checkout/src/talk_to_figma_mcp/server.ts`.
Импортируйте Community plugin по ссылке из upstream README, выберите frame,
подключитесь к тому же каналу через join_channel.
В config.toml разрешите только join_channel, get_document_info, get_selection,
read_my_design, get_node_info, get_nodes_info, get_styles, get_local_components,
export_node_as_image. Другие инструменты, особенно запись в макет, не включайте.

Проверка на браузере Linux обязательна: прочитать выбранный frame, структуру,
стили, экспортировать изображение, отключить plugin и проверить понятную ошибку.
До такой проверки MCP не считается подключённым. Авторизация браузера и запуск
Community plugin выполняются владельцем; desktop/подписка не устанавливаются.
Если не работает, используйте код Figma + скриншот + размеры + оригинальные assets.
Локальный мост не использует REST API Figma, но данные занимают контекст Codex;
это не обещание бесплатного LLM или подтверждённой совместимости браузера.

## Приёмка процесса

На первых трёх реальных задачах запишите: пропущенные требования, повторные
исправления после ревью, лишние остановки, регрессии поведения и выполненные
проверки. Не объявляйте будущую оценку уже проведённой. Обновляйте правила по
конкретным наблюдениям, а не расширяйте их после каждой гипотетической проблемы.

### Подготовленный пилот на текущей машине (3 ноября 2026)

Checkout: `~/.local/share/codex-integrations/talk-to-figma-ddd90f3`, commit
`ddd90f3a6d454ea0b2fc29f1b084f50fd062b880`, package 0.3.5. Зависимости
установлены через `bun install --frozen-lockfile`. Единственная локальная правка
relay задаёт `hostname: "127.0.0.1"`; upstream по умолчанию адрес не ограничивал.
Не обновляйте checkout автоматически. MCP initialize/tools-list проверены,
44 инструмента объявлены; это не проверка подключения к Figma.

1. Запустите relay в отдельном терминале:
   `bun run ~/.local/share/codex-integrations/talk-to-figma-ddd90f3/src/socket.ts`.
2. Откройте макет в браузере и запустите
   [Community plugin](https://www.figma.com/community/plugin/1485687494525374295/cursor-talk-to-figma-mcp-plugin).
3. Запустите новую сессию:
   `codex -c mcp_servers.figma-local.enabled=true`.
4. Через `/mcp` проверьте figma-local, затем попросите подключиться к каналу из
   plugin и прочитать выбранный frame с экспортом изображения. Allowlist уже
   задан в локальном config.toml; запись в макет не разрешена.
5. Закройте plugin и проверьте ошибку отключения. Если браузер не допускает
   localhost WebSocket, используйте fallback, без установки desktop/подписки.

MCP отключён по умолчанию, сервер/сервис не запускается автоматически. Реальный
макет, assets, браузерная совместимость и обработка отключения ещё не проверены.
Для отмены пилота достаточно оставить `enabled = false`; checkout и конфиг не
содержат PAT/OAuth токенов, и никакой Figma-аккаунт от имени пользователя не подключён.
